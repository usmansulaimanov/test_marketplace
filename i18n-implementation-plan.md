# План внедрения i18n (Казахский / Русский) — KitapAll Marketplace

> **Назначение документа:** Пошаговая архитектурная инструкция для Cloud Code / разработчика по добавлению мультиязычности в проект без раздувания зависимостей.  
> **Стек:** React 18, TypeScript, Vite, Zustand (persist), Tailwind CSS  
> **Языки:** Казахский (`kk` — по умолчанию), Русский (`ru`)  
> **Принцип:** Легковесный Zustand-стор с строгой типизацией TypeScript и нулевым оверхедом по внешним библиотекам.

---

## 1. Архитектурный обзор и Trade-off анализ

### Выбранный подход: Zustand Store + TypeScript Dictionaries
Вместо тяжеловесных библиотек (`react-i18next`, `formatjs`), для проекта из ~15 страниц с двумя LTR-языками используется нативный паттерн приложения: **Zustand + LocalStorage Persist**.

```
┌─────────────────────────────────────────────────────────┐
│                    useLanguageStore                     │
│  (state: language = 'kk' | 'ru', t: Translations)      │
└───────────────────────────┬─────────────────────────────┘
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
   ┌──────────────────────┐    ┌──────────────────────┐
   │    Layout / Nav      │    │  Pages & Features    │
   │  - Header (Switch)   │    │  - LandingPage       │
   │  - GlobalSidebar     │    │  - CatalogPage       │
   │  - Footer            │    │  - ProductDetails    │
   │  - MobileBottomNav   │    │  - Seller & Admin    │
   └──────────────────────┘    └──────────────────────┘
```

### Сравнение решений (Trade-offs):
- **React-i18next:** Поддерживает множественные формы (plurals), ленивую подгрузку чанков. **Минусы:** +45-60 КБ в бандл, сложная инициализация, слабая TypeScript-автоматизация для динамических ключей без кодогенерации. *Вердикт: Over-engineering.*
- **Zustand Store + TS Types:** 0 байт новых npm-пакетов, 100% строгая типизация (ошибки опечаток ловятся компилятором `tsc`), мгновенный перерендер без провайдеров (Context Provider), синхронная гидратация с `localStorage`. *Вердикт: Идеально для архитектуры KitapAll.*

## 3. Пошаговые этапы внедрения

### Этап 1: Описание типов переводов (`src/i18n/types.ts`)
Определить строгий контракт словаря `Translations`. Все динамические тексты с переменными (например, количество товаров, цена, имя пользователя) оформляются как функции.

**Ключевые секции интерфейса:**
1. `common` — общие действия (`save`, `cancel`, `back`, `loading`, `search`, `delete`, `edit`, `empty`, `currency`).
2. `nav` — главные пункты навигации (`home`, `catalog`, `wishlist`, `cart`, `profile`, `login`, `logout`, `admin`, `seller`).
3. `header` — плейсхолдеры поиска, подсказки темы и меню.
4. `landing` — заголовок Hero («Заманауи киім & минимализм стилі»), подзаголовок, CTA кнопки, плашки доверия (100% сапа, 1-2 күн жеткізу, 4 категория, Kaspi төлем), категории.
5. `catalog` — фильтры, сортировка (бағасы бойынша, жаңалықтар), поиск, счетчик найденного, сброс фильтров.
6. `product` — карточка и страница товара (өлшемдер, түстер, себетке қосу, бірден сатып алу, қалдық саны, пікірлер).
7. `cart` — корзина, подсчет суммы, оформление заказа, очистка, адрес доставки.
8. `checkout` — модалка и страница подтверждения заказа.
9. `auth` — вкладки входа/регистрации (Сатып алушы / Сатушы), поля ввода, валидация.
10. `client` — личный кабинет покупателя (тапсырыстар тарихы, баланс, чеки).
11. `seller` — панель продавца (тауарлар қосу, қойма, тапсырыстарды өңдеу, қаржы аналитикасы).
12. `admin` — админ-панель (дүкен басқару, тапсырыстар бақылауы, қойманы бақылау).
13. `footer` — категории, разделы помощи, копирайт.
14. `errors` — 404 страница, сетевые ошибки.

### Этап 3: Создание Store и хука (`useLanguageStore.ts`, `useT.ts`)

#### Спецификация `useLanguageStore`:
- **State:** `language: Language`, `t: Translations`.
- **Actions:**
  - `setLanguage(lang: Language)`: переключает язык, обновляет `t = translations[lang]`, устанавливает `document.documentElement.lang = lang`.
  - `toggleLanguage()`: циклически переключает между `'kk'` и `'ru'`.
- **Persist Configuration:**
  - Storage name: `'kitapall-language-storage-v1'`.
  - Дефолтное значение при первом запуске: `'kk'`.
  - On Rehydrate: автоматическая синхронизация `document.documentElement.lang`.

#### Хук `useT()`:
- Возвращает `{ t, language, setLanguage, toggleLanguage }` для лаконичного импорта в компонентах.

## 5. Подводные камни и рекомендации Senior-архитектора

1. **Динамические строковые шаблоны:**
   - Никогда не делай конкатенацию строк в JSX вида `t.items + ": " + count`. Всегда используй функции в словаре: `itemsCount: (n: number) => `${n} тауар``. Это предотвращает ошибки порядка слов в казахской и русской грамматике.
2. **Локализация названий категорий из БД/стора:**
   - Категории в `CATEGORIES` содержат `name` (RU) и `nameKz` (KZ). В компонентах выводи `language === 'kk' ? cat.nameKz : cat.name`, либо сопоставляй через словарь `t.categories[cat.id]`.
3. **Форматирование денежных сумм:**
   - Числа форматируются через `price.toLocaleString('kk-KZ')` или `price.toLocaleString('ru-RU')` с добавлением знака тенге `₸`.
4. **Атрибуты доступности (Aria & Title):**
   - Не забывай переводить скрытые атрибуты: `title`, `aria-label`, `placeholder`, `alt`.
